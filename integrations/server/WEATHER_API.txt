Погодный API, установлен на ТВ с лаунчером 1.14

Работает сейчас:
Open-Meteo: ТВ -> HTTPS ru01.firstvds.proskurn.in -> API Open-Meteo.
wttr.in: ТВ -> API wttr.in; при ошибке -> тот же HTTPS сервер -> API wttr.in.
Это только API погоды. VPN, Home, системные сервисы и трафик приложений не менялись.

RU: 188.120.240.175, proskurnin-weather-api.service.
Python-обработчик слушает только 127.0.0.1:18787 за существующим HTTPS nginx.
Разрешены только GET /tv-api/v1/weather/open_meteo и /tv-api/v1/weather/wttr.
Нельзя передать произвольный URL, хост или координаты. Сейчас фиксирована Москва.
На сервер отправлен только хэш отдельного ключа устройства tv-sdx43. Три ключа
OpenAI/YouTube/TMDB и OAuth JSON не передавались; погодным поставщикам ключ не нужен.
В nginx ограничение 30 запросов/мин с коротким burst. Журнал содержит только
device_id, имя API, статус и длительность; не заголовки или ключ устройства.

Кэш 30 минут, сохраняется в /var/lib/proskurnin-api/weather после перезапуска.
При сбое допускаются сохранённые данные до 6 часов с пометкой на экране.
Сервер делает паузу 60 секунд после отказа поставщика. Поставщики не запускаются
на нашем сервере — он получает и кэширует их JSON. Доступность внешних API и сети
не гарантируется; при недоступности всех маршрутов остаётся локальный кэш ТВ.

Приватный файл на Mac: integrations/server/private/weather-routing.json.
На ТВ: /data/user/0/local.proskurnin.preview/files/weather-routing.json, 0600,
владелец — UID лаунчера. Ключ не входит в APK. Не публиковать эти файлы.
Отдельный исходный ключ: integrations/server/private/weather-device-token.

Как изменить маршруты:
1. Отредактировать OPEN_METEO_API_ROUTE, WTTR_API_ROUTE и WTTR_API_FALLBACK_ROUTE
   в integrations/server/private/api-keys.env.
2. python3 integrations/server/deploy_weather.py
3. python3 scripts/provision-tv-weather.py
4. На ТВ: Настройки -> Погода и поставщики -> Обновить сейчас.
Для этого обработчика пока доступны direct и ru; us отклоняется явно,
пока отдельный US-обработчик погоды не реализован. API других сервисов не затрагиваются.
Период кэша на сервере читается из WEATHER_CACHE_SECONDS. Частота обновления
текущего Android-клиента составляет 30 минут; это разные параметры.

Отключение пользователем:
Настройки (шестерёнка) -> Погода и поставщики -> Сервер погоды: выкл.
Тогда лаунчер использует только прямые вызовы, которые могут быть недоступны.
Повторное нажатие включает серверный путь. Выключатель проверен стрелками и OK.

Отключение серверной функции:
Сначала выключить Сервер погоды на ТВ, затем:
python3 integrations/server/rollback_weather.py --apply
Это снимает только наш nginx location и останавливает/отключает наш weather API.
Данные/ключ сохраняются приватными; остальной nginx, x-ui, SSH не меняются.
Для отзыва доступа одного ТВ заменить hash в /etc/proskurnin-api/weather.json
и перезапустить proskurnin-weather-api; прежний ключ перестанет приниматься.
Для ротации с сохранением работы создать новый случайный weather-device-token
локально с правами 0600, затем выполнить deploy_weather.py и provision-tv-weather.py.

Проверено:
- HTTPS с проверкой сертификата, верные ответы обоих погодных API;
- неизвестный API -> 404; неверный ключ -> 401;
- реальный лаунчер: API open_meteo route=ru OK и погода на экране;
- холодный запуск процесса лаунчера, возврат Home из системных настроек;
- на Android имитация таймаута direct -> реальный ответ wttr.in через RU;
- запрет отправки ключа чужому серверу, остановка новых попыток в фоне;
- выключатель выключен и включён через D-pad, конечное состояние включено;
- кэш, офлайн, истечение кэша и cooldown в автоматической проверке;
- сохранение кэша при реальном перезапуске серверного обработчика.
Сон/пробуждение и полная перезагрузка ТВ в этом этапе не выполнялись.
