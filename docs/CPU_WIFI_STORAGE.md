# CPU, имя Wi-Fi и место на Xiaomi

## Исследование общей загрузки CPU без root

Xiaomi5925 закрывает /proc/stat и cpuinfo для обычного приложения, но разрешает чтение авторизованному ADB shell. Для исследования подготовлен отдельный `stats-bridge.jar`, который работает с UID2000, без root и изменения системных разделов/настроек.

Helper с UID2000 читает только агрегированную строку `/proc/stat` и записывает её в приватный каталог внешних файлов лаунчера. Xiaomi-приложение читает только собственный файл; новые разрешения, сокеты, TCP, root, команды управления, процессы и аккаунты не используются. CPU вычисляется из разности общих счётчиков (0–100% по всем ядрам); idle/iowait не считаются занятой загрузкой.

В1.43.4 и1.43.5 Unix-соединение блокировалось Xiaomi SELinux (`avc: denied { connectto }`) в обе стороны. Проверено, что shell UID Android9 может писать агрегатный файл в `Android/data/local.proskurnin.preview/files`. Universal1.43.6 установлен на Xiaomi; на снимке Home CPU отображается как7%. На Sber сохранено прямое чтение `/proc/stat`; Лайт ТВ установлен и включён, версия5.0.5/code627.
**Ограничение:** helper переживает отключение компьютера от ADB, но завершается после перезагрузки ТВ. Сейчас он вручную запущен в текущем Xiaomi-сеансе. После холодного старта процент не появится, пока helper не запущен с авторизованного компьютера. ADB-ключи в APK не копируются; автозапуск требует отдельного безопасного исследования.

Команды ручного управления helper при необходимости (после перезагрузки снова нужен запуск):

```sh
python3 scripts/build-tv-stats.py
python3 scripts/tv-stats-helper.py --device 192.168.18.144:5555 --model MiTV-MSSP1 start
python3 scripts/tv-stats-helper.py --device 192.168.18.144:5555 --model MiTV-MSSP1 status
python3 scripts/tv-stats-helper.py --device 192.168.18.144:5555 --model MiTV-MSSP1 stop
```

Для текущей сессии перед `start/status/stop` добавить `--adb /private/tmp/proskurnin-platform-tools-current/platform-tools/adb --port 5038`. Остановка затрагивает только этот помощник. Не использовать общий `killall app_process`. JAR в /data/local/tmp занимает несколько КиБ; его можно удалить после STOP. Без helper остальные функции лаунчера сохраняются.

## Wi-Fi

Подсказка: `Сеть · Wi-Fi · <имя сети> · сигнал N/4 · <скорость>`.
SSID берётся только у подключённой Wi-Fi-сети публичными Android API; при LAN/отключении удаляется из состояния. `<unknown ssid>` и управляющие символы не выводятся. Имя сети не сохраняется в настройках и не передаётся на API-сервер. Если прошивка скрывает SSID, глобальная геолокация не включается автоматически.

## Разбор хранилища

Свежие значения получены через Android StorageStatsManager от ADB shell по всем126 пакетам; это не старый кэш dumpsys diskstats. Одноразовый процесс завершился после чтения. Подробная таблица и исходный JSON находятся локально в `reports/xiaomi-cpu-wifi-storage-20261109/STORAGE.md` и `storage-live.json`; файлы аккаунтов/кэш-контент не читались.

Раздел /data:4377МиБ (4,27ГиБ); занято3791МиБ, приложению доступно480МиБ, ещё106МиБ — разница свободного и доступного пространства файловой системы. Примерная разбивка занятого: код/APK/библиотеки/оптимизация обновлённых и пользовательских приложений2853МиБ (2,79ГиБ), данные без кэша728МиБ, кэш10МиБ, остальное около200МиБ — служебное/неатрибутированное и различие методов измерения. Заводской код в /system исключён из общей оценки /data; кэш входит в данные и не учитывается дважды.

Крупнейшие пакеты: Google речь292МиБ, Google Play Services267, Лайт ТВ206, Иви184, ОККО177, Кинопоиск159, Смотрёшка141, Google Cast138, КИОН137. Это объём приложений и данных, не текущая RAM.

Смотрёшка, more.tv,24ТВ, Yokee и v2RayTun вместе занимают около491МиБ. Они лишь кандидаты для обсуждения, **не удалены**. Google речь/Play/клавиатура/голос/HDMI сохраняются. Также остаются отключённый Ram Cleaner (~41МиБ), старый Preview и служба обновления PatchWall (~42МиБ): назначение/нужность последней нужно проверить перед изменением, она не удалялась по одному названию.

## Следующий этап: автозапуск CPU после перезагрузки

- Обычный BootReceiver запускает код с UID приложения и не даёт доступ к /proc/stat. Сам по себе он проблему не решает.
- Кандидат без root: собственный локальный ADB-клиент → 127.0.0.1:5555 → запуск ограниченного CPU-помощника после загрузки. Это пока гипотеза для Xiaomi: нужно проверить loopback из UID приложения, доступность adbd после холодного старта, безопасное хранение отдельного ключа и отсутствие повторных запросов доверия.
- Авторизация нового ADB-ключа требует штатного подтверждения пользователя на ТВ. Ключ Mac копировать в APK или на ТВ нельзя; новая пара должна создаваться локально и храниться приватно. Команды клиента ограничить стартом/остановкой CPU-помощника, без произвольного shell. Возможности ADB шире CPU, это нужно явно согласовать перед включением.
- Источники: [Android — ADB и подтверждение RSA](https://developer.android.com/tools/adb), [AOSP — подтверждение ключа framework](https://android.googlesource.com/platform/system/core/+/3a4aedfcd3354b903aa48a836cb55ee01db9f896/adb/adb.cpp). Они подтверждают механизм авторизации, но **не работоспособность локального автозапуска на этом Xiaomi**.
- Более простой вариант — внешний всегда включённый домашний компьютер, который запускает helper после появления ТВ; без такого устройства автономность не получится. Root/init и перепрошивка ради одного индикатора не предлагаются как текущий шаг.
- До внедрения: отдельный opt-in, отключение и отзыв ключа, пределы повторных попыток, замер RAM/CPU самого помощника, два настоящих перезапуска и сон/пробуждение. Сейчас ничего из этого не активировано и перезагрузка не проводилась.

## Доступ к имени Wi-Fi на Xiaomi — конкретное изменение

Проверка1.40.5: Android вернул скрытое имя и через WifiInfo, и через NetworkInfo; на экране были Wi-Fi/сигнал, без SSID. На Xiaomi `location_mode` первоначально отсутствует (`null`), у лаунчера не было ACCESS_COARSE_LOCATION. Android9 связывает чтение SSID с разрешением местоположения и включённым режимом Location.

В1.40.6 подготовлен запрос только ACCESS_COARSE_LOCATION и переход в системные настройки местоположения по нажатию пользователя. Координаты не запрашиваются, сканирование сетей не запускается. Сам код лаунчера не включает глобальную геолокацию. Для текущего Xiaomi предлагается только после согласия: выдать `ACCESS_COARSE_LOCATION`, установить `settings put secure location_mode 1`, проверить SSID и сохранить исходное `null`. Это глобальная настройка ТВ и потому вынесено на отдельное подтверждение.

Точный возврат исходного состояния Xiaomi:

```sh
adb -s 192.168.18.144:5555 shell pm revoke local.proskurnin.preview android.permission.ACCESS_COARSE_LOCATION
adb -s 192.168.18.144:5555 shell settings delete secure location_mode
```

На другом ТВ восстановить его собственное исходное значение; не копировать `null` Xiaomi на Sber. Окончательный результат/выполненность фиксируются отдельно.

### Выполнено на Xiaomi в1.40.6

Владелец отдельно разрешил доступ к приблизительному местоположению и глобальную настройку для SSID. Выданы ACCESS_COARSE_LOCATION, `location_mode=1`; имя сети видно в правильной позиции на снимке `wifi-1406-verified.png`. Координаты не читались. Исходные значения/команды — `wifi-approved-change.json`; список Home/Voice/Dream совпал с исходным. Другие настройки и пакеты не менялись. CPU остаётся нерешённым пунктом исследования автозапуска, ручной helper не запускался. Standard1.40.6 собран для Sber, не установлен по просьбе владельца.


### Sber: применение в1.41

Владелец попросил применить подготовленные доработки к Sber. Установлен standard1.41, отозван ненужный DUMP; рабочий процент CPU сохранился. Выданы COARSE_LOCATION и location_mode=1. На этой прошивке одного значения location_mode оказалось недостаточно: системный экран продолжал показывать Location «Выкл.». В штатном меню выбран пункт «По точкам доступа Wi-Fi»; после этого `location_providers_allowed` стал `gps,network`, имя Wi-Fi видно между Wi-Fi и сигналом. Лаунчер не запрашивает координаты.

Исходное состояние Sber: location_mode отсутствует/null, location_providers_allowed — пустая строка, COARSE_LOCATION не выдан. Снимки и команды сохранены локально в `reports/sber-update-1406-20261109/`. Для возврата сначала в штатных настройках «Местоположение» выбрать «Выкл.», затем восстановить исходные ключи и разрешение:

```sh
adb -s 192.168.18.247:5555 shell pm revoke local.proskurnin.preview android.permission.ACCESS_COARSE_LOCATION
adb -s 192.168.18.247:5555 shell settings put secure location_providers_allowed '""'
adb -s 192.168.18.247:5555 shell settings delete secure location_mode
```

Проверить, что штатное меню показывает «Выкл.». DUMP возвращать не требуется. Home, VoiceInteractionService и Dream при обновлении сохранились. Имя сети и сырые снимки не включаются в публичный комплект.
