# Переносимый API-сервер

Сервер входит исходниками, а не личной конфигурацией. Для готового существующего сервера достаточно выпустить **отдельную пару токенов для нового ТВ**. Не копировать токены Sber на чужие устройства. Настройки маршрутов относятся только к API нашего интерфейса, не к Google Play, видео в SmartTube, кинотеатрам или Happ.

## Один сервер

Python 3.10+, стандартная библиотека; Python должен доверять актуальным CA. Пользователь ОС без root, приватный каталог 0700, конфигурации 0600. TLS снаружи обслуживает Nginx/Caddy. Backend слушает только loopback.

Из `source/`:

```sh
python3 integrations/server/portable_server.py --init --directory /PRIVATE/PATH/tv-api --base-url https://api.example.org/tv-api/v1/
```

Команда создаёт новый каталог и отказывается перезаписывать существующий. Настоящий домен заменить своим. Дальше **локально** заполнить:

- `worker.json`: `openai_api_key`, `youtube_api_key`, `tmdb_credential`; модели заданы как в существующей реализации и могут быть изменены оператором.
- `relay.json`: тот же `tmdb_credential` для основного маршрута метаданных/постеров; выданную межсерверную авторизацию не менять произвольно.
- `device.json`: только HTTPS base_url и две отдельные учётные строки устройства. Это единственный конфигурационный файл, передаваемый на ТВ.
- `weather.json`: отдельный хеш доступа и интервал кэша. Бесплатные Open-Meteo/wttr.in; ключа Яндекса нет.

```sh
python3 integrations/server/portable_server.py --directory /PRIVATE/PATH/tv-api
```

Процесс держать под обычным supervisor/systemd с доступом пользователя к каталогу; Ctrl+C останавливает все три локальных сервиса. Ничего не копирует на VPS и не меняет firewall/системные сервисы автоматически.

Пример Caddy (домен реальный, TLS сертификат доверенный ТВ; Caddy устанавливается отдельно):

```caddy
api.example.org {
    @weather path /tv-api/v1/weather/*
    handle @weather {
        reverse_proxy 127.0.0.1:18787
    }
    handle /tv-api/v1/* {
        reverse_proxy 127.0.0.1:18788
    }
    respond 404
}
```

Worker в режиме `all` слушает 127.0.0.1:18888, входной API — 18788, погода — 18787. Публикуется только HTTPS; эти внутренние порты наружу не открывать. Reverse proxy должен передавать Authorization, не писать его и тела запросов в журнал, ограничивать тело примерно 1.1 MB и иметь таймаут чтения не менее 50 секунд. Это ограниченный набор API, а не открытый HTTP-прокси.

Первичная проверка: без Authorization любой именованный API должен вернуть 401. После импорта на ТВ — YouTube, погода, текстовый AI, затем голос/озвучка и постеры. Не прикладывать ответ с секретами к отчётам.

## Входной сервер + отдельный вычислительный сервер

- На входном сервере: `--role gateway` (relay.json/weather.json, TMDB и device hashes).
- На вычислительном сервере: `--role worker` (worker.json, провайдерские ключи); worker слушает 127.0.0.1:18889.
- Из входного сервера оператор устанавливает аутентифицированный SSH local-forward 127.0.0.1:18888 → 127.0.0.1:18889 вычислительного. Пример: `ssh -N -L 127.0.0.1:18888:127.0.0.1:18889 WORKER_SSH_ALIAS`. Сначала настроить ключи/known_hosts обычным безопасным способом; не отключать проверку host key.
- Если направление доступа обратное, SSH-туннель настраивает администратор сети; пакет не предполагает доступность конкретного IP. Токен `relay_authorization` и `relay_auth_sha256` должны соответствовать.
- Только gateway имеет внешний HTTPS. Worker не получает открытый публичный порт.

Таким образом пакет пригоден и для одного домашнего сервера, и для двух VPS. Для домашнего HTTPS нужен доверенный сертификат и DNS/локальное разрешение домена; в APK не отключается проверка TLS. На текущем проекте существующие серверы не перенастраивались этим выпуском.

## Где брать ключи

- OpenAI: [API keys](https://platform.openai.com/api-keys), оплачиваемые AI-запросы, веб-поиск, транскрипция и озвучка. Ключ только в worker.json.
- YouTube Data API: [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials), включить YouTube Data API v3. Общий публичный счётчик не требует OAuth. В этой версии канал @ProskurninLife закреплён в реализации; выбор канала в интерфейсе пока отсутствует.
- TMDB: [настройки API](https://www.themoviedb.org/settings/api), Read Access Token или legacy API key. Метаданные, постеры, рейтинги и доступные сведения о провайдерах просмотра. Ключ в worker.json и relay.json.
- Погода/курсы: ключей нет, действуют условия и лимиты поставщиков. Для массового/коммерческого распространения отдельно проверить их тарифы/условия. Погода пока Москва.

Не просим отправлять ключи в чат. OAuth-клиент/токен для будущего эффекта подписчика не нужен для текущего счётчика; функция эффекта пока в ROADMAP. Не переносить личный OAuth при упаковке.

## Отдельные устройства и отзыв

Схема текущего gateway: `device_auth_sha256` — SHA256 строки `Bearer ` + API-токен; `device_auth_hashes` — дополнительные ID → такие же хеши. Погода: `device_token_sha256`/`device_token_hashes` — SHA256 самого погодного токена без префикса. Использовать случайные URL-safe строки минимум 32 символа и уникальные ID; всего до 32 дополнительных устройств. Генератор `portable_server.py --init` помещает первое устройство в карты с ID `tv-primary`; legacy-поля получает случайный невыдаваемый хеш для совместимости формата.

Удаление нужного hash отзывает устройство после перезапуска сервиса; токены не хранить в отчётах. AI-квоты сейчас общие для worker: 50 запросов в сутки и минимальные интервалы. Это семейная установка, не готовая многопользовательская SaaS-платформа. Независимые бюджеты/каналы/города на каждого клиента ещё не реализованы.

## Пять локальных заставок

В комплекте есть код кэша, но нет персональных скачанных роликов. Поместить собственные разрешённые к использованию MP4 в `tv-api/dream-media`: имена a-z/0-9, H.264 до 1080p/30 FPS, каждый до 40 000 000 байт. Для каталога требуется ffprobe (пакет FFmpeg).

```sh
python3 scripts/prepare-dream-catalog.py /PRIVATE/PATH/tv-api/dream-media
```

Нужно не менее пяти файлов. Подготовщик проверяет контейнер/кодек/размер/FPS и создаёт SHA256-каталог. Проверить декодирование на целевом ТВ до выбора DreamService. Лаунчер загружает пять роликов в кэш до 300 МБ, проверяет хеш; во время замены нужен временный запас. Без API/роликов видео не появятся из воздуха; заставка использует свой резерв. Источники с чужими лицензиями автоматически не скачиваются.

## Данные и расходы

AI получает распознанный текст/контекст; телефонное аудио — только по явному нажатию голосовой кнопки через HTTPS и транскрипцию. В режиме разговора можно выключить веб-поиск. Расходы моделей/поиска/речи оплачивает владелец API; текущие цены смотреть у поставщика. Сервер кэширует счётчик, бюджет и необходимые результаты, не записывает произвольные тексты запросов в access log. Закрытые конфигурации, кэш, OAuth и TLS не включать в следующий архив.
