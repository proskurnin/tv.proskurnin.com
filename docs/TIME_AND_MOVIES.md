# Время при старте и качество подбора — 1.36

## Что подтверждено по времени

У SDX-43U4123B есть `mstar-rtc` (`rtc0`), `hctosys=1`. Автоматическое время и часовой пояс включены; пояс Europe/Moscow. После сетевой синхронизации показания `/proc/driver/rtc` и Android совпадают, NetworkTimeUpdateService имеет свежий NTP-кэш. Это не доказывает, что RTC сохраняет верное время при полном обесточивании. В раннем буфере текущего запуска данные уже вытеснены. Будильник AlarmManager на 2036 год — не доказательство текущей даты 2036.

Старый Home брал Date/Calendar непосредственно из системных часов. Фон выбирался по их часу. Обновление UI происходило раз в минуту, без немедленной обработки TIME_SET/TIMEZONE_CHANGED. Интервал погоды считался по currentTimeMillis: коррекция назад могла отложить новую попытку. Возвращение сети само по себе не запускало обновление погоды.

## Изменения

- `LauncherClock` хранит отдельный снимок проверенного времени и elapsedRealtime/boot_count. В пределах одной загрузки отсчёт продолжается по монотонному таймеру, включая сон. Снимок сохраняется раз в минуту, когда открыт Home.
- В новом сеансе правдоподобное RTC предпочтительнее старого снимка; при откате или большом скачке используется последний снимок плюс время текущей загрузки. До проверки время помечено «≈». Это оценка: длительность полного выключения неизвестна. Первый запуск без сохранённого снимка остаётся зависимым от системного времени.
- Проверка берёт Date из HTTPS HEAD существующего API-хоста `ru01.firstvds.proskurn.in`, без токена/персональных данных. TLS проверяется штатно. Не чаще часа после успеха, раз в минуту при ошибке, только при активном Home. Системные часы, NTP, RTC и часовой пояс не изменяются.
- До проверки сохраняется последний проверенный период фона. При уточнении — переход 800 мс, не более примерно 30 кадров/с; после ухода из Home переход прекращается. Это исключает резкую подмену пейзажа, но не обещает знать точный период после длительного выключения без автономных часов.
- Погода сразу показывает сохранённые данные с датой «сохранено …». Возврат сети инициирует обновление; интервалы погоды и текущих курсов переведены на elapsedRealtime. Получить новую погоду без сети нельзя. TIME_SET/TIMEZONE_CHANGED обновляют Home без ожидания минутного тика.

Android рекомендует [elapsedRealtime для интервалов](https://developer.android.com/reference/android/os/SystemClock), поскольку настенные часы могут изменяться. Сохранение времени в данном обновлении относится к отображению лаунчера, а не ремонту RTC прошивки.

## Почему подбор был неточным

После недостаточного числа кандидатов MovieClient вызывал discover/movie и добирал популярные фильмы только по жанрам/длительности/языку. Тематика при этом терялась. Кроме того, выбирался первый поисковый результат TMDB без точного сопоставления названия.

## Подбор 1.36: три карточки и полный список

1. AI собирает до 12 реальных кандидатов заданного типа. «Фильмы» не означает три фильма плюс три мультфильма. Широкая тема «про черепах» включает игровые «Черепашки-ниндзя», а уточнение «настоящие животные» сужает тему. Учитываются отрицания, год, длительность и язык оригинала.
2. TMDB подтверждает точное название/год, жанры, длительность и язык; затем отдельный AI-проход оценивает центральную роль темы по описанию и keywords. Сервер принимает только известные ID и дословную опору; второстепенная/случайная роль отбрасывается. Непроверенные названия не показываются. Модельная оценка всё равно может ошибаться.
3. Если непросмотренных совпадений меньше трёх, выполняется один дополнительный веб-поиск, с теми же ограничениями и проверкой TMDB. При ошибке дополнительного запроса сохраняются уже подтверждённые результаты. Нельзя гарантировать три подходящих произведения для любого сочетания ограничений.
4. Первый экран показывает максимум три карточки. «Найти больше вариантов» открывает прокручиваемую сетку всех уже найденных результатов текущего запроса. «Продолжить поиск» запрашивает следующую порцию, исключая ранее найденные названия; максимум 48 уникальных ID за запрос. Это не полный каталог всех существующих фильмов.
5. Если совпадений меньше трёх, интерфейс сообщает об этом и предлагает другой тип отдельно, с подтверждением. Простое слово «мультфильмы» не запрещает такое предложение; явные формулировки «только мультфильмы», «не мультфильм» подавляют предложение. Распознавание явного запрета использует русские/английские формы; необычные формулировки требуют дальнейших тестов. Автоматического смешивания типов нет.

Используются [метаданные TMDB](https://developer.themoviedb.org/docs/append-to-response), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и при расширении [веб-поиск Responses API](https://developers.openai.com/api/docs/guides/tools-web-search). Только подбор/проверка фильмов используют `movie_model` (по умолчанию gpt-4.1); модель обычного диалога не изменена. Два AI-вызова на первую подборку, до четырёх при повторном поиске; расширение добавляет ещё два и стоимость веб-поиска. Сохраняется дневной лимит 50 AI-вызовов, серверный кэш 24 часа/100 файлов. Для последовательных этапов подбора минимальный интервал вызова 1 с. Лимит тела только movie-endpoint повышен с 4 КиБ до 96 КиБ: прежний nginx отклонял большой список метаданных с HTTP 413.

Ключи остаются на сервере, `store=false`; запросы не пишутся в серверные журналы. Запрос и названия для расширения передаются разрешённому AI-сервису/веб-поиску. Последняя подборка хранится в приватном кэше приложения на ТВ. API-маршруты и VPN не меняются.

### Просмотренное и управление

- Долгий OK на карточке → «Отметить Смотрел». Также есть кнопка «Смотрел» в подробностях по обычному OK.
- «Не смотрел: вкл» скрывает отмеченные фильмы и заполняет первые три позиции следующими из найденного списка. Выключение фильтра снова показывает все найденные фильмы.
- «Просмотрено» → фильм → «Убрать отметку». Очистка всего списка требует отдельного подтверждения.
- История — только ручные локальные отметки по TMDB ID, до 1000. Открытие кинотеатра не считается просмотром; историю чужих аккаунтов приложение не извлекает. Полный список просмотренного не отправляется AI. При расширении передаются названия уже найденного набора, независимо от отметок.
- OK открывает подробности и выбор кинотеатра. Наличие фильма и точный deep link не обещаются; открывается установленное приложение.

Название ограничено двумя строками, описание — пятью. Постер и описание занимают среднюю часть карточки; год, длительность и рейтинг имеют отдельную фиксированную строку. Если источник не сообщил значение, отображается «—». Полное название доступно в подробностях.
