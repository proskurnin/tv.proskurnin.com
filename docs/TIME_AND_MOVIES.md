# Время при старте и качество подбора — 1.35

## Что подтверждено по времени

У SDX-43U4123B есть `mstar-rtc` (`rtc0`), `hctosys=1`. Автоматическое время и часовой пояс включены; пояс Europe/Moscow. После сетевой синхронизации показания `/proc/driver/rtc` и Android совпадают, NetworkTimeUpdateService имеет свежий NTP-кэш. Это не доказывает, что RTC сохраняет верное время при полном обесточивании. В раннем буфере текущего запуска данные уже вытеснены. Будильник AlarmManager на 2036 год — не доказательство текущей даты 2036.

Старый Home брал Date/Calendar непосредственно из системных часов. Фон выбирался по их часу. Обновление UI происходило раз в минуту, без немедленной обработки TIME_SET/TIMEZONE_CHANGED. Интервал погоды считался по currentTimeMillis: коррекция назад могла отложить новую попытку. Возвращение сети само по себе не запускало обновление погоды.

## Изменения

- `LauncherClock` хранит отдельный снимок проверенного времени и elapsedRealtime/boot_count. В пределах одной загрузки отсчёт продолжается по монотонному таймеру, включая сон. Снимок сохраняется раз в минуту, когда открыт Home.
- В новом сеансе правдоподобное RTC предпочтительнее старого снимка; при откате или большом скачке используется последний снимок плюс время текущей загрузки. До проверки время помечено «≈». Это оценка: длительность полного выключения неизвестна. Первый запуск без сохранённого снимка остаётся зависимым от системного времени.
- Проверка берёт Date из HTTPS HEAD существующего API-хоста `ru01.firstvds.proskurn.in`, без токена/персональных данных. TLS проверяется штатно. Не чаще часа после успеха, раз в минуту при ошибке, только при активном Home. Системные часы, NTP, RTC и часовой пояс не изменяются.
- До проверки сохраняется последний проверенный период фона. При уточнении — переход 800 мс, не более примерно 30 кадров/с; после ухода из Home переход прекращается. Это исключает резкую подмену пейзажа, но не обещает знать точный период после длительного выключения без автономных часов.
- Погода сразу показывает сохранённые данные с датой «сохранено …». Возврат сети инициирует обновление; интервалы погоды и текущих курсов переведены на elapsedRealtime. Получить новую погоду без сети нельзя. TIME_SET/TIMEZONE_CHANGED обновляют Home без ожидания минутного тика.

Android рекомендует [elapsedRealtime для интервалов](https://developer.android.com/reference/android/os/SystemClock), поскольку настенные часы могут изменяться. Сохранение времени в данном обновлении относится к отображению лаунчера, а не ремонту RTC прошивки.

## Почему подбор был неточным

После недостаточного числа кандидатов MovieClient вызывал discover/movie и добирал популярные фильмы только по жанрам/длительности/языку. Тематика при этом терялась. Кроме того, выбирался первый поисковый результат TMDB без точного сопоставления названия.

## Новый подбор

1. AI предлагает 0–6 реальных кандидатов. Промпт делает тему центральным требованием, учитывает отрицания, не требует заполнить все места. Для природных тем подходят документальные фильмы, но не случайный морской фон или супергерои вместо реальных животных.
2. Лаунчер сверяет оригинальное/локальное название, год, adult, жанры, длительность и язык по TMDB. Берёт описание и ключевые слова. TMDB остаётся на разрешённом маршруте RU → US при сбое; сторонние приложения/VPN не затронуты.
3. Второй AI-проход оценивает исходный запрос по этим публичным метаданным. Принимаются только известные ID; для принятия требуется дословная опора в описании/ключевых словах. Отсутствующие в источнике доказательства отбрасываются сервером.
4. На экране до трёх результатов. При недостатке точных совпадений нет случайного добора. Ошибка проверки не заменяется непроверенной рекомендацией. Кэш имеет новую версию и не возвращает старые подборки.

Для keywords используется ограниченный [append_to_response TMDB](https://developer.themoviedb.org/docs/append-to-response). Структурированный JSON проверяется по схеме, но [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) сам по себе не гарантирует смысловую точность. Вторая проверка тоже модельная: возможны пропуски хороших фильмов и ошибки трактовки. Нужна дальнейшая оценка на разных запросах.

Два AI-прохода увеличивают время ответа и расходы против одного. Каждый учитывается в прежнем дневном лимите 50 AI-вызовов; кэширование ограничено 24 часами/100 файлами. Ключи остаются на сервере, запрос не пишется в серверные логи; provider store=false. На ТВ сохранение последней подборки остаётся в приватных данных приложения.

## Проверки и возврат

Локальные тесты: откат/скачок времени, новая/та же загрузка, работающий RTC, таймеры, точное название, неизвестные/повторные ID, выдуманная опора, 0–1 результат, ограничения публичных метаданных и allowlist TMDB. Отдельные живые результаты: reports/time-movies-v135/live-quality.json. На ТВ 1.35 выполнен запрос Films about turtles: один документальный фильм про морскую черепаху, метаданные и причина отображены, Back возвращает Home. Службы пульта/помощника/питания сохранены.

Холодный старт без интернета, точность RTC до синхронизации и субъективная плавность фона на панели ещё не проверены: повторной перезагрузки в этой работе нет.
