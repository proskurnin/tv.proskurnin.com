# Кинотеатры, доступность и история — состояние 1.44.3

## Что работает

В карточке фильма «Где смотреть» запрашивает `/movie/{TMDB_ID}/watch/providers` через существующий API-маршрут RU → US при сбое. Регион зафиксирован как Россия, независимо от адреса серверов. Доступность берётся из TMDB/JustWatch, а не из списка установленных приложений; отображаются подписка, аренда, покупка, бесплатно/с рекламой. Один поставщик объединяется в одну строку. Каталог кэшируется сервером до часа; сведения могут запаздывать и не подтверждают права конкретной подписки.

С1.44.3 короткий запрос сначала разрешается как точное название через TMDB `/search/movie`; точные совпадения показываются отдельно от тематического подбора. Формулировки-рекомендации (например, «посоветуй», «подборка», «фильмы про…», «в духе…») обходят точный поиск и остаются в AI-подборе. После выбора фильма полный список предложений сортируется: сначала найденные установленные TV-приложения, затем остальные; внутри группы подписка/бесплатно → реклама → аренда → покупка. Для сторонних каталогов и приложений сопоставление может быть неполным. Установка не подтверждает подписку. Прямые deeplinks на карточку фильма не добавлены.

При пустом ответе написано «в справочнике нет предложений», а не «фильма нигде нет». При сетевой ошибке наличие не подтверждается. Есть явный ручной поиск как резерв. «Источник» открывает страницу TMDB для этого фильма и страны; приложение кинотеатра запускается только отдельной кнопкой, без обещания открыть фильм.

[Документация TMDB](https://developer.themoviedb.org/reference/movie-watch-providers) прямо сообщает, что этот метод не возвращает полные deep links. Атрибуция JustWatch обязательна и отображается в UI. [Партнёрский API JustWatch](https://apis.justwatch.com/docs/api/) требует договор и отдельный партнёрский токен; текущий TMDB-ключ не заменяет его. Такой договор не оформлялся, новый платный сервис не подключён.

Живые проверки 2026-11-09: «Назад в будущее» (105) → Kinopoisk; «Интерстеллар» (157336) → Okko и More TV; «Черепашки-ниндзя» (1498) → Okko. Это снимок справочника, не проверка реального воспроизведения и подписки. На самом ТВ проверен показ Okko в карточке «Черепашки-ниндзя», открытие пояснения и Back.

## Прямой переход к фильму

Только чтением проверены intent-фильтры установленных приложений:

| Приложение | Объявленные входы | Чего пока нет |
|---|---|---|
| Кинопоиск | `https://hd.kinopoisk.ru/film/…` | Подтверждённого сопоставления TMDB ID → ID карточки HD и полного теста перехода |
| Иви | `https://www.ivi.ru/watch…`, `https://ivi.ru/watch…` | Подтверждённого ID конкретного фильма и полного теста перехода |
| Okko | схемы `okko`, `yotaplay` | Подтверждённого формата адреса, ID и полного теста перехода |
| Premier, KION, Zona, LazyMedia | В этом этапе не исследованы | Отдельная диагностика и документированные механизмы |

Наличие intent-фильтра само по себе не доказывает работоспособность конкретной ссылки. Нельзя подставлять TMDB ID вместо внутреннего ID кинотеатра. Для каждого адаптера нужны: сопоставление произведения/года/версии, регион, тип предложения, URL/TV intent из разрешённого источника, дата проверки и тест на установленной версии приложения. Целевой путь: фильм → подтверждённые предложения → точная карточка сервиса. Пока реализован только первый этап с честным резервным переходом.

## История просмотра

Ручная отметка «Смотрел» — список исключений, а не журнал сеансов. Она не доказывает дату, факт полного просмотра или конкретный кинотеатр. Старые отметки не имеют даты просмотра; присваивать им дату установки/отметки задним числом нельзя.

В 1.37 распознаются типичные запросы «смотрел», «видел», «забыл название», «пересмотреть». Для такого поиска локальный фильтр непросмотренного временно обходится, его сохранённая настройка не меняется. UI сообщает, что поиск идёт по описанию, а история кинотеатров не подключена. Промпт не трактует «смотрел на прошлой неделе» как дату выпуска и не должен утверждать личный факт просмотра. Это эвристика для типичных формулировок, не полноценное понимание всей речи.

Для настоящего «что я смотрел на прошлой неделе» нужен журнал с `watched_at`/часовым поясом, исходным сервисом, профилем и ID произведения. Целевая схема:

1. Отдельный разрешённый API/официальный экспорт каждого кинотеатра, с подключением пользователем и возможностью отзыва доступа. Доступ к истории через открытые каталоги TMDB/JustWatch не предоставляется.
2. Нормализация ID в единый каталог, сохранение реального времени просмотра, прогресса и источника; различать просмотр, начало воспроизведения и ручную отметку. Запуск приложения не равен просмотру.
3. Поиск воспоминаний сначала по журналу нужного периода, затем по сюжету. Если журнал не подключён/неполон — сказать об этом и предложить поиск по описанию. Полную историю не отправлять AI по умолчанию; передачу ограниченного набора данных согласовать отдельно.
4. Для сервисов без разрешённого интерфейса — явный ручной журнал с указанной пользователем датой или официальный экспорт. Не извлекать cookies/токены аккаунтов и не собирать экраны через службу кнопок.

У Кинопоиска история есть в профиле ([официальная справка](https://yandex.ru/support/kinopoisk/ru/viewing/history)), но разрешённый внешний API истории для нашего лаунчера не подтверждён. Иви публикует [страницу документации API](https://ask.ivi.ru/knowledge-bases/10/articles/51697-dokumentatsiya-dlya-api-ivi), что само по себе не означает анонимный доступ к каталогам и истории аккаунтов. Общая автоматическая история пока не реализована.


## 1.45.0 — все установленные кинотеатры, 2026-11-22

Sber: Кинопоиск, Иви, Okko, Premier, KION, Wink, Zona и LazyMedia. В «Где смотреть» → «Все установленные» доступен каждый установленный сервис, независимо от наличия предложения в справочнике JustWatch. LazyMedia пока открывается для ручного поиска. В остальных сервисах сначала запрашивается точная публичная карточка по названию и году. Клиент проверяет поддержку HTTPS-ссылки конкретным пакетом; без неё предлагает сайт или поиск в приложении. Неизвестные схемы/ID не конструируются.

Сервер ограничивает домены и пути карточек. Ссылка должна присутствовать среди источников веб-поиска с совпадающими названием/годом либо независимо подтверждаться Movie JSON-LD официальной страницы. Для Иви отдельно сопоставляются VideoObject.name и явный год фильма в заголовке; uploadDate не считается годом выпуска. Сторонние переадресации не выполняются. Кэш публичных результатов — сутки, максимум100 карточек; отмена/уход закрывают запрос клиента. Это не проверка подписки и не гарантия воспроизведения. Ошибка или отсутствие подтверждения оставляет ручной поиск.

Локальный журнал: долгое OK на карточке → отметить дату (сегодня, вчера или календарь) и сервис. Можно записать повторный просмотр; максимум1000 фильмов и50 дат на фильм. Отметка без даты сохраняется отдельно и не попадает в выборку «на прошлой неделе». Периоды считаются по местной дате ТВ, неделя — понедельник–воскресенье. При отсутствии записей не утверждается, что просмотра не было.

История аккаунтов **не импортируется**. Подтверждённого доступа к ней через API/экспорт для этих аккаунтов нет. Открытие приложения и переход на карточку не создают запись просмотра. Данные журнала остаются на ТВ и не передаются AI; синхронизации между ТВ пока нет. Следующий этап — официальный экспорт или авторизованный API конкретного сервиса.

## Локальные источники на Sber — 2026-11-22

Владелец отклонил поддержку/ручные архивы как основной путь и разрешил диагностику локальных источников. Выполнено на подтверждённом SaluteTV/m7332_eu, Standard1.45.0/code85. Установка/настройки/история приложений не изменялись. Xiaomi не подключался. Снимки схем, метаданных и ограниченного набора файлов истории находятся только в игнорируемом `reports/local-watch-history-20261122/private/`.

### Фактические результаты

- `content://android.media.tv/watch_next_program`: обычный ADB shell не видит записей, диагностический root видит41. Из них30 принадлежат YouTube и исключены из исследования кинотеатров. Иви6, Okko2, Кинопоиск3. У6 из11 карточек кинотеатров ненулевая позиция, у10 заполнено название, у11 — ссылка. Это текущий снимок продолжения просмотра, не полная история аккаунтов. KION/PREMIER/Wink/LazyMedia/Zona в этом снимке отсутствуют.
- TvProvider объявляет ACCESS_ALL_EPG_DATA и ACCESS_WATCHED_PROGRAMS как signature|privileged. Наличие root-доступа у диагностики не означает, что обычный APK может читать все записи. Не выдавали разрешений, не делали лаунчер системным. Для автономного сбора нужен отдельный ограниченный адаптер Sber; постоянный root ADB не является решением.
- LazyMedia3.476/code3476: в `data.db` есть `articles`, `position`, `status`. Группа `articles.typearticle=V` содержит8 записей с названиями и `time_added`; в `position`10 записей с ненулевыми позицией/длительностью. Значения `time_sync` нулевые. Значение кода V и смысл time_added ещё не подтверждены кодом/контрольным просмотром; нельзя выдавать это поле за достоверную дату просмотра. Таблицы settings/profiles и их значения не читались.
- Zona3.0.79/code1079: `zonadb` содержит206 записей кэша каталога, таблица params пуста. История найдена отдельно: `shared_prefs/history.xml`, ключ `entity_id_history` — массив3 ID без дат. Есть отдельные файлы позиции, последней серии и просмотренных серий. Прочитаны только эти4 файла; settings, идентификаторы устройств, рекламные данные и streamStorage не читались. Уже существующим отметкам Zona нельзя назначить прошлую дату по mtime файла.
- Частные каталоги обоих приложений закрыты для обычных приложений, run-as отклонён (не debug). Экспортированные поисковые провайдеры не доказаны как источник истории. `su` потребовал пароль и не использовался. Диагностический `adb root` временно применён, каждый проход завершён `adb unroot`; итог uid2000(shell). Перезагрузок не было.
- На ТВ sqlite3 не имеет флага `-readonly`; успешные SQL-чтения выполнены через `file:...?...mode=ro` (фактически `file:/data/.../db?mode=ro`) с `PRAGMA query_only=ON`. Читались схемы и агрегаты, не копировались целые базы/авторизация. В SQLite не выполнялись изменения.

### Контракт будущего адаптера

1. Watch Next — первый кандидат для Кинопоиска/Иви/Okko. Только фиксированные поля публичного контракта и allowlist пакетов, без internal_provider_data/внутренних флагов. Прогресс/время активности хранятся отдельно от ручного «досмотрел»; нулевая позиция и отсутствующее название требуют отдельной обработки. Не отбрасывать короткое видео только по длительности и не называть его фильмом без подтверждения типа.
2. По Android значение last_engagement_time зависит от watch_next_type: CONTINUE — последний просмотр; NEXT — просмотр предыдущего эпизода; NEW — выпуск нового эпизода; WATCHLIST — добавление в список. В историю текущего произведения автоматически принимать только CONTINUE с достаточными метаданными. Источник: https://developer.android.com/reference/android/media/tv/TvContract.WatchNextPrograms . Дата может обновляться сервисом при синхронизации, поэтому до физической проверки это «время, сообщённое приложением».
3. Zona — ID/прогресс можно читать локально; старые записи импортировать без дат. Новое наблюдение — это время обнаружения, не автоматически время просмотра. Проверить сопоставление ID с безопасными метаданными кэша и обновление при реальном просмотре.
4. LazyMedia — подтвердить значение V, единицы позиции/длительности и смысл времени; не переносить time_added в watched_at по названию поля.
5. Доступ реализовывать отдельным помощником Sber: проверка подписи клиента, фиксированные источники, только чтение, предел объёма/времени, отсутствие произвольных путей/SQL и сетевой публикации. Не расширять команды питания для произвольного root-доступа. Root-free Universal/Xiaomi должен честно показывать недоступность источника, а не получать права Sber вслепую.

Результат этапа: локальный путь подтверждён для системной очереди и найдены хранилища двух приложений. Автономный сбор/интерфейс и импорт в журнал ещё не реализованы. Физический просмотр не запускался; существующий фильм на ТВ не прерывался. Версии APK и пульта не менялись.

## Поиск и прямые переходы1.47.0 — 2026-11-22

Точное одиночное совпадение показано широкой карточкой, по OK — большой постер и прокручиваемый сюжет. Постеры загружаются в фоне в ограниченный20МиБ дисковый кэш. CinemaSearch сначала читает публичный контракт [SearchableInfo](https://developer.android.com/reference/android/app/SearchableInfo) / [SearchManager](https://developer.android.com/reference/android/app/SearchManager) установленного выбранного пакета. У provider проверяются владелец и exported; никакого root/учётных данных. Кандидаты сопоставляются по точному нормализованному названию и году: сиквел/ремейк другого года отбрасывается, неизвестный год требует выбора. Произвольные сериализованные Intent не исполняются. Если native не дал подходящего результата, используется прежний проверяемый веб-поиск. Принимаемая приложением HTTPS-карточка теперь открывается сразу после выбора сервиса; иначе явно предлагается сайт или поиск.
