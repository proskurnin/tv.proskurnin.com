# Кинотеатры, доступность и история — состояние 1.44.3

## Что работает

В карточке фильма «Где смотреть» запрашивает `/movie/{TMDB_ID}/watch/providers` через существующий API-маршрут RU → US при сбое. Регион зафиксирован как Россия, независимо от адреса серверов. Доступность берётся из TMDB/JustWatch, а не из списка установленных приложений; отображаются подписка, аренда, покупка, бесплатно/с рекламой. Один поставщик объединяется в одну строку. Каталог кэшируется сервером до часа; сведения могут запаздывать и не подтверждают права конкретной подписки.

С1.44.3 короткий запрос сначала разрешается как точное название через TMDB `/search/movie`; точные совпадения показываются отдельно от тематического подбора. Формулировки-рекомендации (например, «посоветуй», «подборка», «фильмы про…», «в духе…») обходят точный поиск и остаются в AI-подборе. После выбора фильма полный список предложений сортируется: сначала найденные установленные TV-приложения, затем остальные; внутри группы подписка/бесплатно → реклама → аренда → покупка. Для сторонних каталогов и приложений сопоставление может быть неполным. Установка не подтверждает подписку. Прямые deeplinks на карточку фильма не добавлены.

При пустом ответе написано «в справочнике нет предложений», а не «фильма нигде нет». При сетевой ошибке наличие не подтверждается. Есть явный ручной поиск как резерв. «Источник» открывает страницу TMDB для этого фильма и страны; приложение кинотеатра запускается только отдельной кнопкой, без обещания открыть фильм.

[Документация TMDB](https://developer.themoviedb.org/reference/movie-watch-providers) прямо сообщает, что этот метод не возвращает полные deep links. Атрибуция JustWatch обязательна и отображается в UI. [Партнёрский API JustWatch](https://apis.justwatch.com/docs/api/) требует договор и отдельный партнёрский токен; текущий TMDB-ключ не заменяет его. Такой договор не оформлялся, новый платный сервис не подключён.

Живые проверки 2026-11-09: «Назад в будущее» (105) → Kinopoisk; «Интерстеллар» (157336) → Okko и More TV; «Черепашки-ниндзя» (1498) → Okko. Это снимок справочника, не проверка реального воспроизведения и подписки. На самом ТВ проверен показ Okko в карточке «Черепашки-ниндзя», открытие пояснения и Back.

## Прямой переход к фильму

Только чтением проверены intent-фильтры установленных приложений:

| Приложение | Объявленные входы | Чего пока нет |
|---|---|---|
| Кинопоиск | `https://hd.kinopoisk.ru/film/…` | Подтверждённого сопоставления TMDB ID → ID карточки HD и полного теста перехода |
| Иви | `https://www.ivi.ru/watch…`, `https://ivi.ru/watch…` | Подтверждённого ID конкретного фильма и полного теста перехода |
| Okko | схемы `okko`, `yotaplay` | Подтверждённого формата адреса, ID и полного теста перехода |
| Premier, KION, Zona, LazyMedia | В этом этапе не исследованы | Отдельная диагностика и документированные механизмы |

Наличие intent-фильтра само по себе не доказывает работоспособность конкретной ссылки. Нельзя подставлять TMDB ID вместо внутреннего ID кинотеатра. Для каждого адаптера нужны: сопоставление произведения/года/версии, регион, тип предложения, URL/TV intent из разрешённого источника, дата проверки и тест на установленной версии приложения. Целевой путь: фильм → подтверждённые предложения → точная карточка сервиса. Пока реализован только первый этап с честным резервным переходом.

## История просмотра

Ручная отметка «Смотрел» — список исключений, а не журнал сеансов. Она не доказывает дату, факт полного просмотра или конкретный кинотеатр. Старые отметки не имеют даты просмотра; присваивать им дату установки/отметки задним числом нельзя.

В 1.37 распознаются типичные запросы «смотрел», «видел», «забыл название», «пересмотреть». Для такого поиска локальный фильтр непросмотренного временно обходится, его сохранённая настройка не меняется. UI сообщает, что поиск идёт по описанию, а история кинотеатров не подключена. Промпт не трактует «смотрел на прошлой неделе» как дату выпуска и не должен утверждать личный факт просмотра. Это эвристика для типичных формулировок, не полноценное понимание всей речи.

Для настоящего «что я смотрел на прошлой неделе» нужен журнал с `watched_at`/часовым поясом, исходным сервисом, профилем и ID произведения. Целевая схема:

1. Отдельный разрешённый API/официальный экспорт каждого кинотеатра, с подключением пользователем и возможностью отзыва доступа. Доступ к истории через открытые каталоги TMDB/JustWatch не предоставляется.
2. Нормализация ID в единый каталог, сохранение реального времени просмотра, прогресса и источника; различать просмотр, начало воспроизведения и ручную отметку. Запуск приложения не равен просмотру.
3. Поиск воспоминаний сначала по журналу нужного периода, затем по сюжету. Если журнал не подключён/неполон — сказать об этом и предложить поиск по описанию. Полную историю не отправлять AI по умолчанию; передачу ограниченного набора данных согласовать отдельно.
4. Для сервисов без разрешённого интерфейса — явный ручной журнал с указанной пользователем датой или официальный экспорт. Не извлекать cookies/токены аккаунтов и не собирать экраны через службу кнопок.

У Кинопоиска история есть в профиле ([официальная справка](https://yandex.ru/support/kinopoisk/ru/viewing/history)), но разрешённый внешний API истории для нашего лаунчера не подтверждён. Иви публикует [страницу документации API](https://ask.ivi.ru/knowledge-bases/10/articles/51697-dokumentatsiya-dlya-api-ivi), что само по себе не означает анонимный доступ к каталогам и истории аккаунтов. Общая автоматическая история пока не реализована.
