# ТЗ: снимки экранов Proskurnin TV и их сопровождение в Git

Версия ТЗ: 1.0 · 2026-11-13 · статус: на согласовании у владельца.
Базовая версия интерфейса: лаунчер 1.39 (code 51), пульт 1.1.1.

## 1. Цель

Получить полный, воспроизводимый и безопасный для публикации набор снимков интерфейса Proskurnin TV, хранить его в этом репозитории и обновлять вместе с интерфейсом.

Набор используется:
- сайтом проекта https://tv.proskurnin.com/ (основной потребитель);
- документацией (`docs/*.md`) и описанием выпусков в CHANGELOG.md;
- карточкой проекта в личном каталоге.

Репозиторий публичный, поэтому каждый файл в наборе считается опубликованным в момент push.

## 2. Термины

| Термин | Значение |
|---|---|
| Снимок | PNG-файл одного экрана в одном состоянии. |
| Экран | Пункт каталога из раздела 6 с постоянным идентификатором (`id`). |
| Каталог | `docs/screenshots/catalog.json`: что снимать и как туда попасть. Меняется только при появлении или удалении экранов. |
| Манифест | `docs/screenshots/manifest.json`: что фактически снято, когда, с какой версии. Перезаписывается при каждой съёмке. |
| Исполнитель | Тот, кто снимает: агент в этом репозитории на Mac с ADB-доступом к ТВ либо владелец. |
| ТВ | Основной телевизор Sber SDX-43U4123B (Android 9, m7332). Второй ТВ (Xiaomi) в объём не входит. |

## 3. Объём работ

**Входит:**
1. Структура хранения, каталог и манифест (раздел 7).
2. Скрипт съёмки `scripts/capture-screenshots.py` (раздел 8).
3. Первичная съёмка экранов приоритетов P1 и P2 (раздел 6).
4. Правило обновления в AGENTS.md и проверка в `scripts/check-publish.py` (разделы 10, 11).

**Не входит:**
- видеозапись интерфейса (отдельная задача после согласования сайта);
- снимки на Xiaomi и в режиме 4K (до появления переключателя из ROADMAP.md);
- любые изменения прошивки, системных настроек и пользовательских данных ТВ.

## 4. Ограничения безопасности

Это обязательные требования. Они дополняют AGENTS.md и не отменяют его.

1. **Только навигация.** Съёмка не меняет настройки, порядок приложений, сопряжения, историю фильмов и кэш заставки. Допустимы DPAD, OK на пунктах, открывающих экраны или меню, Back и Home. OK на переключателях, кнопках «Сохранить», «Забыть», «Убрать», «Заменить» запрещён.
2. **Перемещение плиток** открывается долгим OK и закрывается только через Back (отмена). Затем проверяется, что порядок приложений не изменился (раздел 8, п. 6).
3. **Меню питания.** Наше меню подменяет системное окно долгого Power (docs/POWER_MENU.md). Нажатие Power, в том числе `input keyevent` с `KEYCODE_POWER`, скриптам запрещено: долгое нажатие на этой прошивке связано с выключением. Меню открывает владелец физическим пультом. Исполнитель делает только `screencap`, затем владелец закрывает меню через Back. OK внутри меню не нажимается.
4. **Без перезагрузки.** Загрузочная заставка снимается не с ТВ, а через рендер (экран `boot`).
5. **Тестовое сопряжение пульта.** Если для съёмки нужно временное сопряжение, его удаляют после съёмки. Сопряжения пользователя не трогают.
6. **Голос и текст.** Используются только синтетические фразы из каталога. Распознанную речь и содержимое полей не сохранять, кроме самих снимков.

## 5. Требования к содержанию кадра (приватность)

На публикуемом снимке не должно быть:

| Данные | Где могут появиться | Что делать |
|---|---|---|
| IP-адреса, порты, адреса пульта | «Пульт с телефона», «Сеть», страница пульта | Не снимать или замаскировать |
| QR-код и код сопряжения | «Пульт с телефона», страница пульта | Замаскировать всегда |
| Имя Wi‑Fi сети, MAC | «Сеть» | Замаскировать |
| Адреса серверов API, маршруты | «Источники», «Погода и поставщики» | Замаскировать или не снимать |
| Аккаунты Google и кинотеатров, аватары | Приложения, кинотеатры | Не снимать |
| Уведомления, тосты ADB, системные диалоги | Поверх любого экрана | Переснять |
| Личная история «Смотрел» | Подбор фильмов | Снимать на нейтральном запросе. Если видны отметки личной истории, переснять |
| Реальная речь владельца | Голос | Только синтетические фразы |

**Как маскировать.** Только сплошной прямоугольник цвета фона экрана, без размытия: размытие можно обратить. Каждая маска записывается в манифест (`masks`: координаты и причина). Других правок кадра нет: ни ретуши, ни кадрирования, ни масштабирования.

Погода, курсы, часы и публичный счётчик YouTube допустимы: это не личные данные.

## 7. Хранение

```
docs/screenshots/
  catalog.json     ← каталог: что и как снимать (ведётся вручную)
  manifest.json    ← результат последней съёмки (пишет скрипт)
  <id>.png         ← один актуальный файл на экран, без версии в имени
```

- Каталог `docs/` уже разрешён в .gitignore, менять .gitignore не нужно. Название `snapshots` не использовать: `check-publish.py` считает такие пути приватными.
- Имя файла — ровно `id` и `.png`. Латиница, цифры, дефис.
- Старые снимки не хранятся отдельными файлами. История — это история Git. Чтобы показать эволюцию интерфейса, снимок версии берётся из коммита этой версии.
- Сайт ссылается на файл по `id` и читает метаданные из манифеста. Переименование `id` — несовместимое изменение, его согласуют с владельцем.

### 7.1 Формат файла

| Параметр | Требование |
|---|---|
| Формат | PNG, RGB или RGBA, sRGB |
| Размер в пикселях | Нативный вывод без масштабирования: для `screencap` ожидается 1920×1080. Фактический размер пишется в манифест. Отклонение от 1920×1080 — повод проверить, а не исправлять. |
| Вес | Не больше 3 МБ (порог «large file» в `check-publish.py`). Сжатие только без потерь (`oxipng -o 4 --strip safe` или аналог). Если файл всё равно больше 3 МБ, задача останавливается, решение принимает владелец. |
| Метаданные | Без EXIF и GPS. Для `photo` удалить обязательно. |

### 7.2 Схема манифеста

```json
{
  "schema": 1,
  "capturedAt": "2026-11-14T12:00:00+03:00",
  "gitCommit": "abc1234",
  "launcher": { "versionName": "1.39", "versionCode": 51 },
  "remote": { "version": "1.1.1" },
  "device": { "model": "SDX-43U4123B", "android": "9", "output": "1920x1080" },
  "screens": [
    {
      "id": "home",
      "title": "Главный экран",
      "priority": "P1",
      "kind": "screencap",
      "file": "home.png",
      "width": 1920, "height": 1080, "bytes": 1534210,
      "sha256": "…",
      "capturedAt": "2026-11-14T12:01:10+03:00",
      "launcherVersion": "1.39",
      "state": "Фокус на первой плитке, день, погода и курсы загружены",
      "masks": [],
      "source": { "mode": "adb", "steps": ["HOME", "WAIT 3000"] },
      "checks": { "uiText": ["Погода"], "notBlank": true, "orderUnchanged": true }
    }
  ]
}
```

Версия лаунчера берётся с ТВ (`dumpsys package local.proskurnin.preview` → `versionName`), а не из исходников. Если версии на ТВ и в `AndroidManifest.xml` текущего коммита не совпадают, съёмка не выполняется.

## 8. Скрипт `scripts/capture-screenshots.py`

**Интерфейс:**

```sh
python3 scripts/capture-screenshots.py --serial <ТВ>:5555 --list
python3 scripts/capture-screenshots.py --serial <ТВ>:5555 --id home --id rates
python3 scripts/capture-screenshots.py --serial <ТВ>:5555 --priority P1
python3 scripts/capture-screenshots.py --serial <ТВ>:5555 --all --dry-run
python3 scripts/capture-screenshots.py --serial <ТВ>:5555 --manual --id power-menu
python3 scripts/capture-screenshots.py --verify      # без ТВ: файлы ↔ манифест ↔ каталог
```

**Поведение:**
1. **Предпроверка, только чтение.** ТВ отвечает. Версия лаунчера совпадает с исходниками (раздел 7.2). Текущий экран — наш Home. Есть сеть. Если что-то не так, скрипт останавливается и ничего не снимает.
2. **Исходный снимок состояния.** Порядок плиток и содержимое «Прочее» до начала берутся через `uiautomator dump`: открывать экраны настроек для этого не нужно. Результат сохраняется в `private/screenshots/` — каталог игнорируется Git.
3. **Навигация.** Шаги берутся из `catalog.json`: `HOME`, `BACK`, `DPAD_*`, `OK`, `LONG_OK`, `WAIT <мс>`, `EXPECT_TEXT <строка>`. Активити лаунчера не экспортированы, поэтому `am start` для них не применяется: только клавиши от главного экрана.
4. **Проверка экрана перед снимком.** Через `uiautomator dump` скрипт убеждается, что на экране есть ожидаемый текст (`EXPECT_TEXT`), а запрещённого нет: «загружается», «недоступна», «Нет сети». Если не вышло, делается до 3 попыток с паузой, затем экран помечается ошибкой и пропускается.
5. **Снимок и проверки файла.** Размеры, вес до 3 МБ. Кадр не пустой: стандартное отклонение яркости выше порога, иначе это чёрный кадр поверх видео или защищённого окна. SHA256.
6. **Возврат.** После каждого экрана выполняются Back до главного экрана и Home. В конце скрипт сравнивает порядок плиток и «Прочее» с исходными. Если есть расхождение, это критичная ошибка: скрипт показывает diff и не меняет манифест.
7. **Запись.** Манифест обновляется атомарно, только по успешно снятым экранам. Записи об остальных экранах остаются прежними.
8. **Маски** задаются в каталоге координатами для каждого `id` и накладываются после снимка. Если на экране с обязательной маской (`settings-remote`) нет описания маски, скрипт его не снимает.
9. **Без побочных эффектов.** Скрипт не делает `adb install`, `pm`, `settings put`, `reboot`, не пишет на ТВ ничего, кроме временного файла `uiautomator dump` в `/sdcard/`, и удаляет этот файл.
10. **Экраны типа `browser`** снимаются отдельным режимом `--remote` через Playwright. **`render`** — режимом `--render`: скрипт копирует `preview-animation.png` из вывода актуального сборщика анимации. **Ручные экраны** (`power-menu`) — режимом `--manual --id power-menu`: скрипт ждёт Enter в терминале, проверяет через `uiautomator dump`, что меню на экране, снимает и не нажимает никаких клавиш.

Тесты: `tests/test_capture_screenshots.py` проверяет разбор каталога, проверку манифеста, маскирование и детектор пустого кадра на синтетических изображениях. Тестам ТВ не нужен.

## 9. Порядок первичной съёмки

1. Согласовать с владельцем это ТЗ и формулировки синтетических запросов (раздел 6).
2. Сделать структуру `docs/screenshots/`, `catalog.json` для P1 и P2, скрипт и тесты.
3. Прогнать `--all --dry-run`: шаги навигации и ожидаемые тексты без снимков.
4. Снять P1, затем P2. Каждый кадр просмотреть глазами на соответствие разделам 5 и 6.
5. Выполнить `--verify` и `python3 scripts/check-publish.py`.
6. Сделать отдельный коммит `Screenshots: initial set for launcher 1.39 / remote 1.1.1` с записью в CHANGELOG.md (раздел «Снимки экранов», без новой версии лаунчера).

## 10. Сопровождение

**Когда переснимать:**

| Событие | Что переснять |
|---|---|
| Выпуск лаунчера или пульта с видимыми изменениями | Затронутые экраны, их перечень указан в записи CHANGELOG |
| Изменение минорной версии (1.39 → 1.40 и т. д.) | Все P1 |
| Новый экран или пункт настроек | Добавить в каталог и снять в том же выпуске |
| Удалён экран | Удалить `id` из каталога, файл и запись из манифеста. Если экран был на сайте, предупредить владельца |
| Раз в месяц при активной разработке | Полная съёмка P1 и P2 |

**Как связать с выпуском:** снимки коммитятся вместе с выпуском или следующим коммитом с пометкой `Screenshots: <версия>`. В записи CHANGELOG выпуска есть строка вида «Снимки: обновлены `home`, `settings-background`» или «Снимки: без изменений интерфейса».

**Добавить в AGENTS.md** (выполняет исполнитель в рамках задачи):

> - Снимки интерфейса — `docs/screenshots/`, правила — docs/SCREENSHOTS.md. Выпуск с видимыми изменениями переснимает затронутые экраны (`scripts/capture-screenshots.py --id …`) и перечисляет их в CHANGELOG. Новый экран сразу добавляется в каталог. Кадры с адресами, QR, кодами сопряжения и личными данными не публикуются.

## 11. Расширение `check-publish.py`

Добавить проверки:
1. Каждый файл в `docs/screenshots/*.png` есть в манифесте, и его SHA256 совпадает.
2. Каждый `id` из манифеста есть в каталоге.
3. Ни один PNG не тяжелее 3 МБ, без EXIF.
4. Для экранов с обязательной маской в манифесте записана хотя бы одна маска.

## 12. Критерии приёмки

1. В `docs/screenshots/` лежат все экраны P1 и P2 из раздела 6. Каждый соответствует описанному состоянию.
2. `--verify` и `check-publish.py` проходят без замечаний.
3. В манифесте указаны версии лаунчера и пульта, совпадающие с установленными на ТВ, и коммит.
4. Владелец просмотрел все кадры и подтвердил, что на них нет личных данных.
