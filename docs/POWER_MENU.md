# Меню питания — исправление 2026-11-08

Установлены лаунчер 1.32.2, пульт 1.1.1 и ресурсный модуль PowerFocus 1.1. Пользователь подтвердил перемещение голубого выделения физическими стрелками и запуск помощника после закрытия меню. **Исправлена навигация, но не выполнение команд питания.** Последующая проверка пользователя: «Выключить» не действует, «Перезагрузить» выключает ТВ без повторного запуска, «Скриншот» работает. Причина ещё не установлена; отдельно нужно отличить полное выключение от сна/ожидания. Задача добавлена в ROADMAP.md. Холодный старт после исправления навигации ещё требует проверки.

## Повторная диагностика 2026-11-09

На установленном Android 9 команды не перепутаны в интерфейсе: `PowerAction.onPress` вызывает `shutdown()`, `RestartAction.onPress` — `reboot(false)`. Overlay PowerFocus меняет ресурсы фокуса и не заменяет обработчики.

Подтверждено байткодом текущего `services.odex` и поведением на ТВ:

- `ShutdownThread.shutdown` при отсутствующем `persist.sys.EnableSTR` использует значение `true`. В этой ветке при обычном режиме (не FactoryTest) метод возвращается без `shutdownInner`. После выбора «Выключить» меню закрылось, но сохранились Awake, boot_id и работа Home. Это объясняет отсутствие выключения.
- Системное меню запускает `ShutdownThread.reboot` с причиной `userrequested`. Запись от 02:26:22 содержит `Rebooting, reason: userrequested`, перед этим выполнены shutdown broadcast, остановка ActivityManager/PackageManager и радио. Это не вызов `shutdown` вместо `reboot`.
- Последний успешный ADB-перезапуск имел причину `adb`. Различие причин пока не доказывает причину остановки после системного меню. ТВ не вернулся в сеть за 150 с. После физического Power пользователь увидел заставку и наш Home; получен новый boot_id, причина загрузки reboot,userrequested. Это подтверждает перезапуск с задержкой до физического включения, но не локализует неисправность до конкретного уровня firmware/PM.

Постоянное `persist.sys.EnableSTR=false` не применялось: `PhoneWindowManager.interceptPowerKeyUp` меняет при этом и поведение короткого Power. `factory.long_press_power_off` также не является безопасной постоянной заменой: влияет на выбор поведения долгого Power. Нельзя объявлять питание исправленным по изменению подсветки или перестановке подписей. Framework, загрузчик, ENV и режим быстрого сна в этой проверке не менялись.

Локальные снимки и журнал: `reports/ui-power-v134/`. Реальные команды выключения/перезапуска отдельно разрешены пользователем для текущего теста. Исправление выполнения питания **пока не установлено**.

## Подготовленный обход v1 — ещё не установлен

В исходниках 1.34.1 подготовлено собственное меню из трёх действий, открываемое вместо конкретного окна `com.android.systemui.globalactions.GlobalActionsDialog$ActionsDialog`. Короткий Power и остальные системные диалоги не перехватываются. Используются метаданные класса/пакета, без чтения дерева экрана. По умолчанию настройка `power_menu=false`; при недоступном помощнике остаётся исходное системное меню.

Новый отдельный помощник `PowerBridge` принимает через локальный Unix-сокет только PING, OFF и REBOOT, только от UID установленного лаунчера с закреплённым сертификатом. Нет TCP, адресов, паролей, произвольных команд/аргументов и доступа со стороны веб-пульта. Команды ограничены интервалом 60 секунд. Нужен root для штатных защищённых операций питания; существующий помощник пульта не расширяется.

- OFF: уведомление ACTION_SHUTDOWN, sync, затем фиксированный `/system/bin/reboot -p userrequested`. Несмотря на имя бинарника, параметр `-p` задаёт **shutdown,userrequested** для `init`, а не reboot. Это не принудительный syscall: [исходник Android 9 reboot.c](https://github.com/aosp-mirror/platform_system_core/blob/android-9.0.0_r1/reboot/reboot.c) и строки бинарника этого ТВ совпадают по интерфейсу. [init/reboot.cpp](https://github.com/aosp-mirror/platform_system_core/blob/android-9.0.0_r1/init/reboot.cpp) останавливает службы, синхронизирует и размонтирует файловые системы. Этот путь обходит дефектную Java-проверку EnableSTR; он не полностью идентичен ShutdownThread и ещё не проверен на железе.
- REBOOT: фиксированный `svc power reboot adb`: обычная процедура PowerManager/ShutdownThread с явной причиной adb. Работоспособность именно этого сочетания надо проверить: последний успешный adb reboot и системное svc — разные входы.
- Скриншот: штатный GLOBAL_ACTION_TAKE_SCREENSHOT через уже включённую службу специальных возможностей; вызывается после закрытия нашего меню.

Установщик `scripts/install-proskurnin-power-actions.py --apply` добавляет только помощник (без команд питания); `--restore --apply` останавливает и убирает только этот помощник. APK обновляется отдельно, после этого настройка включается пользователем/через проверенный интерфейс.

Кандидат: `builds/proskurnin-power-actions/src/`, `proskurnin_power.rc`, `scripts/build-proskurnin-power-actions.py`, PowerMenuActivity/PowerControl в лаунчере. Установка добавит `/vendor/etc/proskurnin-power/power-bridge.jar` и `/vendor/etc/init/proskurnin_power.rc`, обновит APK и включит настройку меню после отдельного согласования этого обхода. SystemUI, services.odex/vdex, быстрый сон, MBOOT/ENV не переписываются.

Отключение: настройки лаунчера → «Меню питания Proskurnin» → выкл; немедленно возвращается прежнее системное меню. Для полного удаления остановить только `proskurnin_power`, убрать его два файла в локальную резервную папку; если запущен вручную, завершить только проверенный PID этого класса. APK можно вернуть из копии без очистки данных. Проверить отключение и штатное меню до реальных команд питания.

## Что обнаружено

Первоначально ActionsDialog фокусировал полноэкранную подложку. PowerFocus 1.0 перенаправил фокус к пунктам, но этого оказалось недостаточно. В исходном `global_actions_item` отсутствовал фон состояния фокуса; серый фон «Скриншота» был оформлением панели и не показывал выбор. ADB перемещал системный фокус без видимого изменения картинки.

В контрольном тесте физическая стрелка не меняла выбор при активном фильтре VoiceKeyService, а после временного отключения только этой службы передвинула выбор с первого на второй пункт. Точная внутренняя ошибка прошивки не установлена. Обычный возврат false из onKeyEvent не обеспечивал ожидаемого поведения в этом диалоге.

## Что изменено

- PowerFocus 1.1 сохраняет `afterDescendants` и добавляет голубую подсветку на основе штатного Android selector. Сохраняются размеры, идентификаторы и системные обработчики действий. idmap содержит только `layout/global_actions_item` и `layout/global_actions_wrapped`.
- VoiceKeyService по метаданным окна узнаёт системный диалог и снимает FLAG_REQUEST_FILTER_KEY_EVENTS на время его работы. Отложенные действия отменяются. Кнопки помощника и настроенные кнопки приложений в системном диалоге специально не запускают приложения.
- При возврате окна приложения фильтр включается обратно. Прошивка не всегда посылает TYPE_WINDOW_STATE_CHANGED после Back, поэтому уже разрешённая служба ввода веб-пульта дополнительно наблюдает только тип/фокус окон и отправляет факт возвращения приложения. Содержимое прочих окон не читается, дерево не обходится, названия/тексты не передаются. Получатель требует существующее разрешение уровня signature; пробное сообщение от ADB shell отклонено.
- VoiceKeyService сохраняет `canRetrieveWindowContent=false`. Для надёжного возврата после Back используется включённая служба `local.proskurnin.remote/.TextInputService`; при её отключении возврат по событию нового окна приложения остаётся, но мгновенный возврат после закрытия диалога не гарантируется. Эту зависимость нужно учесть при переносе на другие ТВ.

Сборка overlay требует **родные** SystemUI.apk и framework-res.apk. Приватные Android ID нельзя брать из более нового SDK. В Android 10 и ниже собственные ссылки overlay могут конфликтовать с ID целевого пакета, поэтому добавленная подсветка использует только штатные ресурсы Android ([документация RRO](https://source.android.com/docs/core/runtime/rros#resolve-resources)). Фильтрация использует [FLAG_REQUEST_FILTER_KEY_EVENTS](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#FLAG_REQUEST_FILTER_KEY_EVENTS).

Обычное обновление статического overlay через adb install отклонено прошивкой. Обновлён отдельный `/vendor/overlay/ProskurninPowerFocus.apk`, проверен idmap и заменён его кэш с сохранением прав. Затем перезапущен **только SystemUI**, без перезагрузки ТВ. Исходный `/vendor/overlay/ProskurninPowerMenu.apk`, включающий меню долгого питания, сохранён. Системные приложения не отключались.

## Откат

Локальные резервные файлы (не в Git): `reports/power-focus-v133/ProskurninPreview-1.31.1.apk`, `ProskurninRemote-1.1.apk`, `PowerFocus-installed-1.0.apk`, `powerfocus-original.idmap`. APK устанавливаются поверх с сохранением данных; если прошивка запрещает понижение versionCode, требуется сборка прежнего кода с увеличенным номером версии и тем же ключом. Не удалять приложения и данные для обхода запрета понижения: это потеряет настройки и сопряжения.

Для полного удаления только экспериментального ресурса меню, при доступном root ADB и writable vendor:

```sh
adb -s TV_IP:5555 root
adb -s TV_IP:5555 wait-for-device
adb -s TV_IP:5555 shell 'mkdir -p /data/local/tmp/proskurnin-rollback && mv /vendor/overlay/ProskurninPowerFocus.apk /data/local/tmp/proskurnin-rollback/ProskurninPowerFocus.apk && sync'
adb -s TV_IP:5555 unroot
```

После этого требуется отдельно согласованная перезагрузка для пересканирования overlay. Не удалять `ProskurninPowerMenu.apk`. При возврате именно PowerFocus 1.0 восстанавливаются его APK и соответствующий idmap из резервной копии с исходными правами, затем перезапускается SystemUI. Возврат старой версии вернёт и прежнее поведение меню.

После смены режима ADB проверить локальный помощник веб-пульта: ручной процесс может завершиться вместе с ADB. Ресурсный модуль предназначен для SystemUI данного телевизора и не переносится на Xiaomi автоматически.
