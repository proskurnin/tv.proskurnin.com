# Альтернативный интерфейс 4K — исследование 2026-11-09

## Результат первого этапа

На Sber **настоящий вывод 4K из обычного приложения пока не подтверждён**. Три проверенных варианта SurfaceView проходят через итоговый буфер 1920×1080, который затем растягивается на матрицу 3840×2160. Создание Canvas 3840×2160 само по себе не означает 4K на экране.

Лаунчер остаётся 1.38, в Full HD. Переключатель, выдающий увеличенный внутренний буфер за настоящий 4K, не добавлен. Системные настройки, `wm size`, параметры панели, драйверы и загрузчик не менялись. Перезагрузки не было. Xiaomi проверен только чтением, диагностический APK на него не устанавливался.

## Подтверждённые данные

| Параметр | Sber SDX-43U4123B | Xiaomi MiTV-MSSP1 / nino |
|---|---|---|
| Android | 9 / API 28 | 9 / API 28 |
| Матрица и текущий тайминг HAL | 3840×2160 | 3840×2160 |
| Слой интерфейса / доступный режим DisplayManager | 1920×1080 / 60 Гц | 1920×1080 / 60 Гц |
| GPU | Mali-G52, OpenGL ES 3.2 | Mali-470 MP, OpenGL ES 2.0 |
| Итоговое окно OSD до масштабирования | 1920×1080 → 3840×2160 | 1920×1080 → 3840×2160 |
| Проверка отдельной поверхности | Три варианта проверены | Пока только исходная диагностика |

У Xiaomi свойства загрузки дополнительно сообщают размер 55 дюймов и панель CSOT. Это данные прошивки, не прочитанная заводская наклейка.

На Sber активная конфигурация указывает:

```text
/vendor/tvconfig/config/model/Customer_1.ini
  m_pPanelName = /vendor/tvconfig/config/panel/UD_VB1_8LANE_CSOT_URSA.ini

/vendor/tvconfig/config/panel/UD_VB1_8LANE_CSOT_URSA.ini
  m_wPanelWidth = 3840
  m_wPanelHeight = 2160
  osdWidth = 1920
  osdHeight = 1080
```

Сам файл не доказывает, что изменение двух полей включит безопасный 4K: нужно исследовать загрузку конфигурации, CRC, выделение памяти и ограничения аппаратного композитора. Автоматически изменять этот файл или пересчитывать таблицы загрузчика нельзя.

## Проверки на Sber

Отдельное приложение без разрешений и регистрации Home открывало тестовый рисунок, закрывалось через Back/при уходе с экрана либо автоматически через две минуты.

| Проба | Буфер приложения | Что показал аппаратный композитор |
|---|---|---|
| SurfaceView + аппаратный Canvas | 3840×2160, RGBA8888 | Skip Client; итоговый Client Target 1920×1080 |
| SurfaceView + программный Canvas | 3840×2160, RGB565 | Skip Client; итоговый Client Target 1920×1080 |
| Четыре SurfaceView, каждая занимает четверть экрана | Четыре буфера 1920×1080 | Все четыре Skip Client; единый Client Target 1920×1080 |

В первом случае журнал подтвердил `canvas=3840x2160 hardware=true`. Но SurfaceFlinger/HAL одновременно показал источник 3840×2160, кадр назначения 1920×1080 и конечное окно `src:1920 x 1080, dst:[0,0,3840,2160]`. Это подтверждает потерю 4K-разрешения в проверенном пути композиции. Снимок обычным screencap также не является измерением разрешения самой матрицы.

Замеры подготовки одиночных тестовых кадров не являются FPS или тестом производительности лаунчера. Память, длительную плавность и нагрев настоящего 4K-режима имеет смысл оценивать после подтверждения сквозного вывода.

Локальные исходные отчёты (не публикуются): `reports/interface-4k-v139/{sber,xiaomi}/`. Суффикс каталога обозначает исследование предполагаемого следующего этапа, а не выпущенную версию 1.39.

## Почему нельзя просто увеличить wm size

`wm size` меняет логическую конфигурацию Android и может затронуть все приложения; он не гарантирует изменения аппаратного буфера OSD. Это не соответствует желаемому переключателю только нашего лаунчера.

[Android описывает SurfaceView как путь к полному разрешению на некоторых 4K-телевизорах с интерфейсом 1080p](https://developer.android.com/media/media3/ui/surface). Реальный драйвер текущего Sber в проверенных режимах всё равно выполняет промежуточное уменьшение. [Предпочтительный режим окна](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#preferredDisplayModeId) выбирается только из доступных режимов и может игнорироваться системой; на этих ТВ опубликован только режим 1080p.

## Следующий этап и границы

2026-11-09 пользователь разрешил рассматривать **системный 4K**, включая влияние на другие приложения. Прежнее ограничение «только наш лаунчер» больше не является требованием к результату. Далее исследуем системный OSD; конкретные изменения прошивки и перезапуск рассматриваются после подготовки проверяемого плана возврата.

1. Только чтением исследовать, существует ли у этой прошивки отдельный путь вывода графики в 4K или переключение OSD на уровне одного окна. Найденный `/vendor/etc/uhd_keeping_packages.xml` содержит лишь комментарий про сохранение 4k2k30hz и пустой список: это **не доказательство** поддержки 4K-интерфейса по пакетам.
2. Проверить необходимость системных изменений и влияние на другие приложения. Если они нужны, сначала подготовить конкретный обратимый эксперимент: точные файлы/значения, исходные копии и хеши, независимый способ отката при отсутствии изображения. Затем отдельно согласовать изменение и возможный перезапуск. Простую правку osdWidth/osdHeight без этих проверок не предлагать как готовое решение.
3. После подтверждения сквозного вывода реализовать переключатель Full HD / 4K, Full HD по умолчанию, предварительный просмотр с таймером подтверждения, автоматический возврат и сброс. Размеры элементов сохраняются; текст и векторы перерисовываются, растровые источники не получают выдуманных деталей.
4. Проверить поверхность и ограничения Xiaomi отдельно, затем нагрузку, управление, диалоги, приложения, сон и холодный старт. Результат Sber не доказывает результат Xiaomi, несмотря на похожую схему OSD.

## Воспроизводимый диагностический APK

Сборка не подключается к телевизору и ничего на нём не меняет:

```sh
python3 scripts/build-proskurnin-4k-probe.py
```

Создаётся игнорируемый `builds/proskurnin-4k-probe/DisplayProbe.apk`, подписанный отдельным локальным тестовым ключом. Ручной тест переключает текущий экран; запускать только на выбранном устройстве в согласованное время:

```sh
adb -s <ТВ>:5555 install -r builds/proskurnin-4k-probe/DisplayProbe.apk
adb -s <ТВ>:5555 shell am start -n local.proskurnin.displayprobe/.SurfaceProbe --es mode rgba
adb -s <ТВ>:5555 shell dumpsys SurfaceFlinger
adb -s <ТВ>:5555 shell input keyevent 4
```

Повторить с `--es mode rgb565` и `--es mode tiles`. Проверять не только размер Canvas, но и Client/Device composition, Source crop, Client Target и конечный размер окна HAL. Проба рисует статический рисунок, не запускает бесконечную анимацию и не меняет системное разрешение.

После проверки удалить только диагностическое приложение:

```sh
adb -s <ТВ>:5555 uninstall local.proskurnin.displayprobe
```

Это не удаляет лаунчер, его настройки или сопряжения телефонов.
